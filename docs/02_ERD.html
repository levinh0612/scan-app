Mô hình dữ liệu (ERD)

CSDL: SQLite, file data/contracts.db (bật chế độ WAL nên có thêm file contracts.db-wal/-shm khi chạy — bình thường; mọi truy cập qua backend/contracts.py, có khóa luồng _lock). Lược đồ (SCHEMA) tự tạo khi server khởi động — không cần chạy migration thủ công.

2. Từ điển dữ liệu#

2.1 Bảng contracts#

Cột Kiểu Ràng buộc Ý nghĩa / quy tắc
id INTEGER PK, tự tăng Khóa nội bộ, dùng trong URL API
ma TEXT UNIQUE Mã hiển thị HD + yyMM + - + số thứ tự 4 chữ số của tháng
created_at TEXT NOT NULL Thời điểm lập, ISO YYYY-MM-DDTHH:MM:SS
status TEXT NOT NULL, mặc định dang_cam dang_cam, da_chuoc, thanh_ly, huy
ho_ten, cccd, ngay_cap, dia_chi, sdt TEXT — Thông tin khách (cắt tối đa 300 ký tự). ngay_cap dạng dd/mm/yyyy
bks, nhan_hieu, so_loai, so_khung, so_may, mau TEXT — Thông tin xe (cắt tối đa 300 ký tự)
so_tien INTEGER mặc định 0 Tiền gốc (đồng, số nguyên)
le_phi INTEGER mặc định 0 Lệ phí thỏa thuận lúc lập
so_ngay INTEGER mặc định 0 Tổng số ngày cầm (cộng dồn khi gia hạn)
tu_ngay TEXT — Ngày bắt đầu, ISO
den_ngay TEXT — Hạn hiện tại, ISO; đổi khi gia hạn
bks_k, khung_k, may_k, cccd_k, ten_k TEXT có chỉ mục (trừ ten_k) Bản chuẩn hóa (bỏ ký tự lạ, chữ hoa) của trường tương ứng, dùng so sánh trùng. Không sửa tay — sinh tự động khi lập/sửa
dedupe TEXT UNIQUE cccd_k\|bks_k\|khung_k\|tu_ngay\|so_tien; chặn tạo trùng khi bấm 2 lần. Hợp đồng hủy đổi thành huy:<id> để giải phóng khóa
closed_at TEXT NULL Thời điểm chuộc/thanh lý/hủy; NULL khi đang cầm
closed_amount INTEGER NULL Chuộc: tổng tiền khách trả. Thanh lý: giá bán. NULL/0 = chưa nhập
note TEXT mặc định '' Ghi chú (tối đa 500 ký tự)
nguon TEXT NOT NULL, mặc định may_tinh Nơi lập: may_tinh hoặc dien_thoai

Chỉ mục: ix_c_bks(bks_k), ix_c_khung(khung_k), ix_c_may(may_k), ix_c_cccd(cccd_k), ix_c_status(status, den_ngay), ux_c_dedupe(dedupe) UNIQUE.

2.2 Bảng events (lịch sử, chỉ thêm)#

Cột Kiểu Ý nghĩa
id INTEGER PK —
contract_id INTEGER NOT NULL FK → contracts.id Chỉ mục ix_e_c
at TEXT NOT NULL Thời điểm, ISO
type TEXT NOT NULL Loại sự kiện (bảng dưới)
days INTEGER Số ngày (tạo, gia hạn)
amount INTEGER Số tiền (gốc lúc tạo; phí gia hạn; tiền chuộc; giá bán)
den_ngay TEXT Hạn sau sự kiện (tạo, gia hạn)
note TEXT Ghi chú; với sua là danh sách trường: cũ → mới; với huy là lý do
type Phát sinh khi Ảnh hưởng báo cáo

gia_han Gia hạn Cộng amount vào doanh thu theo ngày at
chuoc, thanh_ly Đóng hợp đồng Chỉ làm lịch sử; số liệu lấy từ contracts.status/closed_*
mo_lai Mở lại Lịch sử
sua Sửa thông tin Lịch sử (cũ → mới)
huy Hủy Lịch sử (lý do)
Ghi chú

Vì báo cáo chuộc/thanh lý dựa trên contracts.status chứ không cộng theo events, "Mở lại" tự động bỏ khoản đó khỏi báo cáo.

2.3 Ràng buộc nghiệp vụ nằm ở code (không có trong DDL)#

  • Phải có ít nhất một trong bks, so_khung, so_may khi lập/sửa.
  • Chỉ gia hạn/chuộc/thanh lý khi status = dang_cam.
  • Không mở lại hợp đồng huy; không sửa hợp đồng huy; hủy phải có lý do.
  • Khóa ngoại được bật (PRAGMA foreign_keys=ON) và không có ON DELETE CASCADE: delete_hard phải xóa events trước rồi mới xóa contracts.

3. Dữ liệu ngoài SQLite#

data/
├── contracts.db                 # CSDL chính
├── settings.json                # cài đặt tiệm + PIN đã băm (pin_hash, pin_salt)
├── offsite.json                 # thư mục sao lưu ngoài (nếu đã cấu hình)
├── anh/<mã hợp đồng>/
│   ├── cccd-sau.jpg             # JPEG ~70%, cạnh dài ≤ 1280 px (~150–250 KB)
│   └── ca-vet.jpg
└── backup/
    ├── contracts-YYYYMMDD.db    # 1 bản/ngày, giữ 30 bản gần nhất
    └── truoc-khoi-phuc-*.db     # bản tự lưu trước mỗi lần khôi phục, giữ 5 bản
.run/                            # trạng thái chạy (pid, cổng, cấu hình in print.json) — không phải dữ liệu nghiệp vụ
logs/server.log                  # nhật ký server

Biến môi trường đổi vị trí dữ liệu (dùng cho thử nghiệm): SCAN_DB, SCAN_IMAGES, SCAN_SETTINGS.

Dọn ảnh#

Ảnh của hợp đồng đã chuộc/thanh lý/hủy bị xóa sau anh_giu_ngay ngày (tính từ closed_at). Xóa hẳn hợp đồng cũng xóa thư mục ảnh của nó.

Sao lưu#

  • contracts.backup() dùng API backup của SQLite (an toàn khi đang ghi). Chạy tự động mỗi ngày (vòng lặp nền) và ngay sau mỗi thay đổi (sửa/hủy/chuộc... qua _backup_soon).
  • Gọi lại trong ngày thì ghi đè bản của ngày đó; chỉ giữ 30 bản mới nhất.
  • Khôi phục (restore) kiểm tra bản sao hợp lệ, tự lưu bản hiện tại thành truoc-khoi-phuc-*.db rồi mới ghi đè.
  • Sao lưu ngoài máy: cấu hình một thư mục (USB, Google Drive đồng bộ, ổ mạng) — mỗi lần sao lưu sẽ chép thêm sang đó.

4. Lệnh in (RAM)#

Lớp JobStore (backend/jobs.py), không ghi đĩa:

Trường Ý nghĩa
id Chuỗi hex ngẫu nhiên (secrets.token_hex(5))
status cho_in, dang_in, da_gui, da_ra_giay, loi
bks, chu Biển số, tên chủ xe (che bớt nếu chưa nhập PIN)
snapshot Bản chụp dữ liệu hồ sơ (tối đa 40 khóa, mỗi giá trị ≤ 500 ký tự) dùng để in lại
giới hạn Tối đa 30 lệnh, tự xóa sau 12 giờ, mất khi khởi động lại

5. Truy vấn tiêu biểu (để kiểm tra nhanh bằng sqlite3)#

-- Hợp đồng đang cầm sắp/đã quá hạn
SELECT ma, ho_ten, bks, den_ngay FROM contracts
WHERE status='dang_cam' AND den_ngay <= date('now','+3 day') ORDER BY den_ngay;

-- Vốn đang bỏ ra
SELECT COUNT(*), COALESCE(SUM(so_tien),0) FROM contracts WHERE status='dang_cam';

-- Lịch sử một hợp đồng
SELECT at, type, days, amount, note FROM events
WHERE contract_id=(SELECT id FROM contracts WHERE ma='HD2611-0001') ORDER BY id;
Lưu ý

Mở DB bằng công cụ ngoài khi server đang chạy chỉ nên đọc. Muốn sửa dữ liệu, dùng chức năng trong app để có lịch sử và sao lưu.
